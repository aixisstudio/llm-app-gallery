開発者のための AI 活用法

## 実際にAIが開発に役立つところ
| タスク | 使い方 |
|---|---|
| ボイラープレート・試験 | 日々の最大の勝利 |
| レガシーコード理解 | ファイルを貼り付け、ウォークスルーを依頼 |
| リファクタリング | 「これを引き継ぎ、それを簡素化」 — ディファクターレビュー |
| デバッグ | トレース+コードを貼り付け、仮説をランク付け |
| ドキュメント・コメント | ファーストドラフト — 自分を磨く |
| 試作 | 営業時間 → 投げかけコード |

## ワークフロー
- **プラン → エージェント → レビュー** — 仕様書を書くと、エージェントはコードを書いて、すべての行を読みます
- **差分レビュー** — 決して盲目を受け入れない; 独自の差分を説明するためにモデルを尋ねる
-**マルチモデルチェック** - 危険な変更に関する第二の意見
- **Tests-firstプロンプト** — 実装前にテストを依頼

## 🧱 インテグレーションパターン
| パターン | 使用 |
|---|---|
| チャットの完了 | Q&A 代 |
| 関数呼び出し | API を呼び出すモデルを聞かせて |
| RAG | *your* docs/data からの回答 |
| エージェント | ツールで複数のステップのタスク |
| 楕円形 | 試作・バージョン回帰試験 |

## ⚠️ アンチパターン
- 生成されたコードをプロットするブラインドパスティング
- 秘密/PIIをプロンプトにリークする — データがどこにあるか([Snitch](https://github.com/aixisstudio/Snitch)がすべてのアウトバウンド接続を表示されます)
- 狭いコンテキストではなく、コードベース全体をダンプ
- 「AIが書いた」からテストをスキップする
